# 地形勘测软件缺口与开发优先级

实施更新：任务定义、离线处理、质量报告和配置核对四项已实现，入口为`scripts/offline_survey.py`，见[使用说明](offline_survey.md)。随后已接入[实时上行与主工作台](live_survey.md)，支持任务质量及成果包导出。原盘点与测试记录在下文保留；P1误差扰动研究、P2长任务／回环与实体通信验收仍属于后续范围。

首次盘点日期：2026年10月19日。目标是把现有原型整理为可复现、可解释的地形勘测软件。车辆基线保留，分段积分候选继续冻结；盘点阶段没有修改算法、物理、控制、导航或验收阈值，没有启动物理仿真。

当前已经能采集、重建、查看和导出地形，也已有精度评价工具。主要缺口是任务、数据、质量判定与成果交付还没有形成统一的软件流程。下一步先完成一个不依赖硬件的离线勘测任务包，复用已有实现，再处理影响测绘结论的误差和观测几何。

本清单依据[仿真用途与精度要求](simulation_validation_scope.md)、当前源码及离线检查。它是开发安排，没有把暂定的5 cm、5°等值升级为用户已批准的正式指标。

## 已有的软件能力

| 环节 | 已有实现 | 已知边界 |
| --- | --- | --- |
| 任务与采集 | 工作台保存起点、矩形区域、场景和车型；自主任务记录半径、时间预算、动作与故障 | 仿真任务、活动范围与评价范围分别管理，尚缺统一的勘测任务契约 |
| 观测档案 | NPZ保存传感器坐标点、时间戳、相机位姿及可选车体位姿；原子保存、损坏拒绝 | 前端普通NPZ与专用同步深度评价记录不是同一证据等级；不能仅凭普通档案宣称绝对精度 |
| 重建与地图 | 体素融合、单层高程／坡度／残差粗糙度、采样充分度与无效拟合状态 | 残差和充分度不等于测量不确定度；历史点云不会自动随SLAM回环更新 |
| 展示与导出 | 三维地图、轨迹、逐帧回放、测距、PLY、OBJ和DEM ASCII导出 | 导出格式已具备，任务范围、质量图、坐标与来源说明尚未统一随成果包交付 |
| 精度评价 | 固定参考与区域、逐格状态、C/P/S、高程RMSE和坡度MAE、中文图表和CSV | 主评价入口绑定专用Gazebo同步记录与场景参考；不直接覆盖任意外部深度数据 |
| 勘测策略与导航 | 多种观察策略、预算限制、Nav2执行、取消与故障记录 | 已有功能不等于全场覆盖或策略稳定优势；车型和预测代理的适用性仍需核对 |
| 离线验证 | 几何、存取、导出、评价、回放API和规划器已有测试 | 一部分纯计算逻辑与ROS节点导入耦合；本宿主不能运行所有相关测试 |

因此，下一步应复用`TerrainMap`、现有评分器和导出器。DEM、回放和几何评分都不需要重新从零实现。

## 软件缺口及优先级

P0是下一轮小范围开发的核心；P1随后按证据推进；P2在任务规模或需求触发时安排。

| 优先级 | 缺口 | 对地形勘测的影响 | 可在无硬件条件下完成的交付 |
| --- | --- | --- | --- |
| P0 | 统一勘测任务与成果定义 | 无法稳定回答本轮测哪里、算到何时、哪些格子计入完成度 | 版本化任务文件，明确区域、坐标、预算、地表表达、分辨率、阈值来源和数据来源；校验采集／活动／评价范围的一致性 |
| P0 | 通用离线数据契约与统一入口 | 算法可复用，但真实数据迁入仍依赖专用仿真目录和隐含约定 | 先支持规范化的点云／深度与位姿文件夹、现有NPZ适配；统一校验、回放、重建、导出和报告。ROS与Gazebo作为可选数据源 |
| P0 | 成果质量与证据索引不完整 | 观测充分、拟合成功、几何达标和整任务完成容易被混称；历史版本难追溯 | 统一状态和成果清单，保留缺测／无效格与失败，绑定源码、任务、输入、坐标及参考哈希；区分仿真、合成和物理数据 |
| P1 | 误差影响缺少统一的复算流程 | 难以判断地图误差来自深度、定位、姿态、时间还是拟合 | 复用现有投影／表面诊断，加入受控偏差的离线案例及分距离、分地形结果。先输出敏感性与适用范围，不编造置信概率 |
| P1 | 观察预测与实际配置未统一核对 | 预测可见面积、动作时间和可达观察位姿可能有系统偏差 | 从实际CameraInfo／TF／运行参数生成对照清单，对视场、相机位置、速度代理和车辆包络做只读一致性检查 |
| P1 | 工作台缺统一的勘测成果总览 | 使用者能看到地图，但还难在一个入口读清任务范围、缺测和精度资格 | 展示任务边界、有效／无效／未测状态、数据来源、参考状态、暂定目标和结果包；无参考时准确度显示未知 |
| P2 | 历史位姿修正与地图再融合流程 | 长距离或回环后，旧点云仍可能保留原位姿误差 | 保留逐帧原始观测，接受另存的修正位姿并生成新版地图，记录前后差异；保留原图及原始误差结果 |
| P2 | 长任务分块与多会话对齐 | 单会话容量限制会阻止更大范围勘测，多次任务也不能直接拼接 | 先定义容量到限行为、分块及重载，再考虑多会话。无可信坐标关系的会话不能自动合并 |

已有软件的若干具体差异解释了这些优先级：

- `validate_task`保存矩形区域，而自主活动及现有几何评价以起点／中心和半径为主。应明确三者对应关系，避免将不同面积当同一任务分母。
- 普通NPZ主要记录点、位姿、时间和简要元数据；专用评价还需要原始深度、CameraInfo、运行坐标契约及参考。补通用适配时，证据不足应输出“准确度不可评价”，不能填充Gazebo专用字段冒充核验。
- DEM已输出NODATA，质量状态不应被抹掉。其当前JSON包含格网与高程统计，缺少统一任务ID、坐标／高程基准、标定与位姿版本、质量图及输入清单；需要随结果包补齐，而非只增加一种文件格式。
- 规划器采用60°水平视场、车前0.435 m等代理，R5深度仿真声明73°；动作时间按0.20 m/s估算移动，控制器期望速度为0.16 m/s。它们是否足以影响勘测结论须核对，不能把差异直接视为已定位缺陷，也不在本轮调参。
- 当前统一Nav2 footprint为0.86×0.72 m，地形入口未按R5重新设置。需要与实际碰撞包络和安全余量对照，不能为增加可达面积直接缩小它。
- 单会话限制5000帧、500万原始点，读取档案还有150 MB限制。现阶段应先按有限任务交付，不直接承诺50×50 m全场长期勘测。

## 第一项开发的具体范围

下一步优先交付“离线勘测任务校验与成果报告入口”。输入来自已有档案、合成数据或规范化文件夹；使用当前基线算法。暂不扩展到新探索策略、完整三维SLAM、真实土壤预测或复杂GIS服务。

### 任务与数据

任务文件至少声明勘测区域、局部坐标定义与米制单位、时间来源及截止时刻、地表格与体素尺寸、评价目标和版本。首版选择一种明确的区域表示；其他形状应明确拒绝或标为未支持，不能静默换成外包框。已有矩形与圆形协议继续按原定义复现。

数据契约区分原始观测、相机内参、相机／车体位姿、标定版本以及可选独立参考。合成、Gazebo与物理采集具有独立来源标记，不能只用自由文字推定“真实”。在没有测地坐标或高程基准时，成果明确使用会话局部坐标，不猜测EPSG或海拔。

先做规范化文件夹和现有档案适配即可。ROS bag、厂商驱动和所有外部数据格式不需要在首版一次实现。

### 输出成果

一个结果目录包括任务与输入清单、原始来源索引、重建档案、点云、高程图、逐格质量状态、指标及阅读报告，并保存必要的单位、坐标、版本与校验值。复用已有PLY、DEM、CSV和报告实现，OBJ按表达适用性选用。

报告分开回答：

1. 哪些区域已观测，哪些区域能够输出地表，哪些仍未测或无法拟合？
2. 有独立参考时，哪些格子在冻结的高度／坡度门槛内，误差和分母是多少？
3. 无参考、坐标对应不明或来源不足时，哪些精度结论暂时不能给出？
4. 实际截止时刻、故障、输入遗漏和范围限制是什么？

没有参考也能导出地图与观测支持状态，准确度字段保持未知。覆盖分母按事前任务和表达范围声明；不能用已测区域反推任务范围，也不能把没有参考的区域自动判为合格。仿真真值仅进入离线评价。

### 完成条件

- 在无硬件、无运行中ROS/Gazebo的环境中，能从声明的输入复算到结果包；依赖和命令明确。
- 已知平面／斜面案例能核对高度、坡度和坐标；同一档案的保存、重载、回放与导出保持约定的数值一致性。
- 缺少内参／位姿／单位／时间对应、重复时间戳、数据损坏等情况有明确结果；不产生伪造精度。允许保存原始材料，但拒绝无依据的达标结论。
- 缺测、拟合失败、边缘／多层等表示范围外区域与误差超限分别保留；NODATA不自动补平。
- 截止后的观测不计入本次成果；故障不从任务总表删除；输入不被覆盖，输出来源可核查。
- 现有档案和评分版本继续可复现；新增格式采用新版本，基线、参数和旧成绩不变。

这项工作完成后，再做P1误差诊断和前端总览。届时才能判断需要改的是数据处理、传感器几何还是策略预测。

## 历史结果和文档需要统一入口

当前工作树中的`paper_handoff_report.md`仍包含“全面超越”“实车仿真”“能效”等强结论；主仓库[基准目录说明](../../MoonCar/benchmark_results/README.md)已明确部分数据属于旧单次批次、均未通过全部暂定条件，并区分后续重算资料。两者不能无条件互相代替。

下一轮成果索引应绑定实际数据批次和指标定义：观测面积、有效拟合面积、达标地表分S与单位位移收益分别报告；面积／米不能直接当作耗电能效。保留旧文档的历史属性，不把其文字当作实车、沉陷、统计优势或当前版本验收证据。本轮只指出这一交付缺口，没有改写历史论文稿或重新计算策略排名。
