# 两种地形策略的自主探测录像对照

2026-11-16。原策略 baseline 与候选 elevation_neighborhood_v1 各执行一次自然自主探测。规划器共用 surface_view_v2，依据各自实际收到的地形观测选点。

两组均使用原始 V2 地形 survey_v2_native、R5 支承配置、rgbd_window 定位、起点 (0.5,0,0)、全场边界 [-15,-15,15,15]，距起点最远 8 m。每组预算为 180 仿真秒，启动后的云台补观测计入预算。每组墙钟采集上限为 1800 秒，安全或健康条件失效可提前停车。

录制实际 Gazebo GUI 屏幕，每墙钟秒 3 帧，保留抓取时刻。GUI 主镜头跟随车辆，轨迹与地图图层在录制后按时间叠加。左上角小地图只使用当时已经收到的导航图和定位，北向固定。底部保留四轮状态，缺测显示为空。原始墙钟视频与按仿真时间播放的完整成片均保留。

两组同一源码与安装核验版本、同一资源设置，顺序运行 baseline 后运行候选。记录任务时间、前进与扫描动作、轨迹、观测覆盖、故障原因及定位连续性。本次只有一组运行，结果用于观察行为差异，重复数不足以估计成功率。

执行前修复验证工具的生命周期查询。丢失的服务回复在 2 秒墙钟后取消并重新查询，只有实际得到四个节点的新鲜 active 回复才开放测试派发条件。车辆自己的就绪与保护链继续生效。记录 GUI 跟随模式与相机位姿的确认。
