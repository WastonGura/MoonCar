# 短暂 ROS participant 段归属：正式启动通过，校准收尾时序失败

本轮独立上限 10 次，实际 3/10 后按首个失败停止。两个正式 R5/坡道 v2 启动检查整轮通过；第一个 D=0 校准的基础采集、输入、逐步记录和活跃进程容量核验通过，但交付包装器在关闭桥接后仍要求远端段有活跃所有者，整轮保留失败。校准正式计数 0/4，三场景专门检查和兼容检查未运行，默认仍 legacy。

无 Gazebo 的真实 ROS 发送端退出测试复现了远端删除映射：没有历史记录的快照失败；提前取得独占锁、PID、启动身份、段与锁的设备号/inode 后，确认原 PID 已退出、文件已删除并且映射 inode 完全相符，新的检查通过。不是直接忽略未知映射。旧失败轮次的具体未知段仍不补判。

本轮新增生命周期观察在 ROS 启动前运行，有界元数据队列 8192、独立写线程；正式准备检查、71 项相关回归通过后冻结。库、QoS、相机、车辆和控制均不改。

第三次的活跃终点登记表全部通过：桥接自有 8 MiB，其他实际 ROS participant 自有 512 KiB，纯归档/启动进程没有 participant。其后原运行器先关闭 peer 进程，再调用主记录器 close；包装器的另一次接收端映射核验发现原桥接文件仍在，但持锁 PID 已退出，错误地用关闭后的状态否定运行时配置。该轮 result.json、完整原始记录及失败都保留。

停止时执行签名一致，冻结源码在 campaign/source/ 留存。软件 328 项、前端 3 项及固件通过。只关闭本轮容器。之后针对关闭时序的工具修正及新矩阵位于 ../r5-dds-release-20261009/；不复用本轮两个成功结果补足新矩阵，也不跨签名配对。
