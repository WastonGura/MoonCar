## 必须在仿真前补齐的具体问题

1. **缺失会被算成失触。** 评估器只汇总 `state==1`，没有核对每步各轮是否有完整源记录。我分别输入右前轮记录完全缺失、`state=-1` 未知、`state=0` 显式空快照三种人工数据，三种结果都为 `fr_zero_contact_steps_count=3`。缺失/未知不能用于证明轮子离地或零接触力。修正后需拒绝前两种，只把完整 `state=0` 作为空快照。
2. **承诺的因果分析还没实现。** 当前只算左前轮与一条接缝的相交，并输出接触/载荷异常步数及全程水平合力 RMS。没有四轮与邻边相交、具体接触事件位置/时刻、连续空快照区间、累计/事件冲量、整车质心速度比较、恢复与基线对照；不能回答哪次几何变化导致哪次受力变化。脚本命令行入口仅打印等待信息，不接收运行目录。
3. **测试副本和执行入口未交付。** 五个交付文件中只有 JSON 计划、评估 Python 和说明，没有两个可加载的世界副本，也没有消费计划的运行入口。JSON 中引用已有模型路径不等于已经生成并核对测试副本。
4. **调度起始需要保留真实记录。** 原轮次有 200 步准备，静置从 200 到 5200，运动到 25200，停车到 28200。28 s 是三阶段窗口时长，原末端实际是 28.2 s。新计划未明确准备段，而评估器仍写死 5201–25200。应复用原调度，从实际阶段回执读取边界并核对整数步，不能忽略两者的不一致。
5. **共线重叠求交错误。** 共线且重叠的人工母线与目标接缝被函数判为不相交。应处理此边界，避免把沿接缝重叠漏掉。二维母线投影相交只是几何关联，轮子离地时仍可能投影相交，必须与实际接触状态、高度分别记录。

这些是原因诊断所需的最小工具问题，不要求增加物理参数搜索、更多仿真矩阵或整车验收。
