# 2026-10-08 工作日志：DDS 图片采集容量修复验证

## 本轮结果

在固定测试负载下，图片采集断档的原因得到确认：桥接发布进程的 512 KiB DDS 共享内存段容量不足，仍有接收者等待的缓冲被回收，导致图片分片失效和不完整重组被后续消息替代。

仅将桥接发布端共享内存段设为 8 MiB 后，两轮修复试验和四轮独立采集校准全部通过。恢复原容量后，两轮再次出现同一失效机制与图片空档，因果对照成立。

## 执行记录

- 前一轮 `r5-shm-repair-20261008` 因未构建及加载项目 ROS overlay 启动失败，计为一次尝试，原记录保留；未执行运动窗口，不属于 DDS 或车辆故障证据。
- 增加仿真前项目包、必要执行程序、源码哈希及观察器完整性检查，补齐实际 DDS QoS、库路径、段容量与日志排空核验。
- 用户另行授权新容器、新目录及最多 12 次预算。本轮完成原安装库两轮、内部观察库两轮、8 MiB 修复两轮、恢复原容量两轮、新校准四轮，共 12/12 次。
- 四轮校准顺序为 1 ms、0.5 ms、1 ms、0.5 ms。RGB、深度最大归档间隔均为 1.0 仿真秒，满足不超过 1.5 秒的门槛。
- IMU、关节、姿态、安全速度、逐物理步记录、输入窗口、暂停 flush、文件回执及队列排空均通过；两组轮速目标积分的等效距离差及转角差均为零。

## 保持的边界

使用原 Jazzy 镜像，4 CPU、6 GiB、512 MiB 容器共享内存、ROS_DOMAIN_ID=95 与独立 Gazebo partition。保留 D=0 候选、车辆、摩擦、地形、DART 修复库、安全中继、起停调度、相机参数、QoS、发现方式和传输集合。

8 MiB 仅用于独立测试环境的桥接发布进程，接收段保持 512 KiB。正式默认值、生产控制 profile、公共话题、launch 参数和网页 API 未更新。本轮结论只覆盖既定负载，不用于补判此前失败记录或证明所有图片丢失问题都已消除。
