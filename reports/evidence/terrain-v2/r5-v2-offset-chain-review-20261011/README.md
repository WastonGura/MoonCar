## 已复现的对照失效

`check_chain.py` 从当前源码提取实际嵌套 `prepare` 函数执行。仅最底层文件准备替换成临时目录复制；不导入ROS，不运行进程，也不启动Docker/Gazebo。

| 阶段 | 最终车辆出生位姿 | ContactObserver 数量 | StepObserver 数量 |
|---|---|---:|---:|
| 输入平移副本 | `0.05 0 .03 0 0 0` | 1 | 1 |
| 原单轮/原点准备函数之后 | `0 0 .03 0 0 0` | 2 | 1 |
| runtime 再添加逐步观察器之后 | `0 0 .03 0 0 0` | 2 | 2 |

原因明确：新副本先由外层 `prepare` 复制进去；`check_r5_turn_slip_round.py` 又添加接触观察器；`check_r5_origin_round.py` 的准备函数随后无条件把出生位姿改为 `0 0 .03 ...`；`check_r5_runtime.py` 再添加已有的逐步观察器。输入副本设置正确并不能证明最终加载世界仍保留X=0.05。

因此当前两轮可能实际使用相同X，而重复观察器会产生同路径写入冲突。要检查实际传给 `gz sim` 的最终文件，而不只是JSON计划或 `world_consumed` 输入路径。

## 资格判定也存在可复现遗漏

使用原第14轮结果原样重放新的资格计算，10mm超限可正确被登记为诊断几何结果。但分别把 `image_content.passed` 或 `origin_qualification.passed` 设为false，同时保持最终 `passed=false`，新包装器仍判 `eligible=true`。

这是人工资格探针，不是旧轮次真的图片损坏。它说明当前检查列表遗漏了原资格结果的一部分。应保留进入几何筛选前的完整资格状态，只允许解除单独的10mm结果门槛，不能把同一轮的其他数据失败一起解除。

## 其他实际执行准备项

- dry-run 拟把当前准备目录挂载为 `/evidence`，但该目录没有调用链要求的 observer、contact-observer、allocator、turn-slip、turn-models、模型manifest及test-startup资源。新容器依赖必须真实组装并核验，不能仅打印环境字符串。
- 实际执行分支没有把子进程退出码/超时与读到的 `eligible` 一并判定，也未拒绝已有轮次目录。不能读旧回执判定新尝试成功。
- 事件文件使用固定路径和 `open('w')`；CLI是在事件文件写入之后才检查汇总输出是否存在。因此JSON拒覆盖不等于全部证据受到保护。
- 载荷变化使用硬编码 `[4.34,2.80,3.10,4.64] N`，与原轮次静态左右对称载荷不符。每轮载荷变化应按自己的运动前稳定窗口计算，防止给正常载荷制造虚假的不对称基准。

这些应通过实际文件准备重放、旧记录和故障替身检查解决，不需要增加新的物理实验。
