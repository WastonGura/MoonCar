# MoonCar 三策略正式对照协议 v1

本协议在实验前固定研究问题、源码版本、场景、起点、顺序、重复次数、预算、指标、缺失数据处理和停止规则。目标是比较三种策略的表现与适用条件，不预设地表补采获胜。

## 固定设计

- 三种在线策略：`nearest_view_v1`、`coverage_view_v1`、`surface_view_v1`。
- 三个场景：50×50 米综合场地、可见斜坡、可见曲面。
- 每场景两个合法起点，每个“场景×起点×策略”重复三次。
- 共 54 轮；每轮重新启动 Gazebo、SLAM、地图记录和同步证据捕获。
- 每轮最多 90 仿真秒，距实际起点最多 8 米；提前停止、执行失败和不可评价结果全部保留。
- 三种策略共用导航、传感器、安全限制、记录链和评价器；复杂离线补采模型不参与。

主要结果为 `mapping-acceptance-v1` 的综合得分 S。同时报告覆盖率、几何合格率、高程和坡度误差、耗时、路程、动作失败及结束状态。阈值继续使用冻结的暂定仿真标准，不在看到结果后修改。

## 统计口径

先在每个“场景×起点”条件内汇总三次重复。总体比较以六个条件的策略均值为单位，不把同一场景的重复运行伪装成新的独立地形。报告均值、中位数、标准差、范围和逐轮数据；探索性成对检验采用六个条件均值的精确符号翻转检验，并对三组比较作 Holm 校正。

统计结果只说明这六个预设条件。无优势、负向差异、运行失败和场景依赖都属于有效结论。

## 停止规则

只运行预先声明的 54 轮。若编排发生故障，立即停止并诊断；只能在记录修复原因后继续尚未开始的预定轮次，已经完成但成绩不佳的轮次不得替换。不得自动增加场景、重复次数或专项调参。

运行前复核：

```bash
python3 reports/evidence/terrain-workbench/formal-strategy-protocol-20260914/check_protocol.py
```

实际命令固定在 `run_formal.sh`。输出写入 `tmp/ros_acceptance/formal-strategy-20260914`，`campaign.log` 保留全过程；`COMPLETE` 或 `FAILED` 表示批次终态。

启动批次第一次执行在试验 1 前因 Bash `nounset` 与 ROS 环境脚本不兼容而退出，未生成场景计划或试验数据。该日志和失败时间已保留；协议 v1.1 只把 `nounset` 移到两个既有 ROS 环境加载之后，策略、场景、起点、重复、预算、指标和停止规则均未改变。
