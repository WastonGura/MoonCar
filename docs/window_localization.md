## 实际运行链路

RGB/深度与曝光时刻的IMU、云台TF → 持续特征跟踪 → 多关键帧局部窗口 → 普通帧查询／后台联合优化 → 原曝光时间的位姿、TF和健康状态 → 导航、地形采集与自主任务。

固定视向与云台视向共用同一定位后端。两版都按曝光时间查询相机到车身的变换；固定安装时变换恒定，云台运动时变换随实际关节反馈变化。两版的定位输出均为车身位姿。

当前端选出的三维特征沿一个方向过于集中时，允许在同一帧已测特征中按弱方向分布重新选点一次，参考 [Zhang 等对几何退化方向的分析](https://www.cs.cmu.edu/~kaess/pub/Zhang16icra.html)。重选保留原观测数量和图像格预算，仍需通过原空间检查，且已有局部地图时，关联旧地图的点本身也必须通过空间检查。日志中的 `metric_spread_retry` 记录重选前后的分布及是否接受。这项改动处理单帧选点，云台主动换视角属于后续独立验证。

`rgbd_window_odometry.py`是唯一定位发布者，输出仍兼容`/mooncar/laser_odometry`、`/odometry/filtered`、`odom→base_footprint`和`/mooncar/laser_odometry/status`。主题名为兼容已有消费者保留，实际后端通过状态中的`localization_backend=rgbd_window`标识。新模式不会同时启动旧RGBD定位进程，也不把旧位姿或真值作为新方案输入。

使用已离线比较的576点跟踪预算、6关键帧、96求解观测、96列预热，后台单运行／单待处理任务。位置与完整协方差直接取窗口结果，不另造更小的协方差；该协方差仍是模型条件下的估计，未宣称已标定全局后验。

关键帧保留原0.5秒定时更新，并在当前有效共享点降到48以下、距上次请求至少0.1秒且后台空闲时提前构建，避免在视野变化中等到低于原24点连接要求才更新。原有效性检查和事务提交保留；该修复的同录像比较及在线复核见[持续断链修复](../reports/WINDOW_TRACK_CONTINUITY_REPAIR_20261102.md)。

新方案关闭旧主动回访流程，普通探测仍保留目标选择、导航范围、地形限制和运动许可。原0.3仿真秒观测有效期、0.5墙秒接收有效期、连续3帧就绪等保护保留。过期、重复、错曝光、坐标原点改变、无效协方差或源故障不发布新位姿。短暂失效仍会停车，恢复就绪后用新许可继续任务。

## 启动与安装

现有开发容器已安装新入口。常规工作台仍由`./scripts/start_workbench.ps1`启动，下一次启动默认加载新模式。已有进程不会因源文件更新自动重载；本次验证用隔离8766服务，结束后已关闭测试容器，主8765没有运行中的旧服务需要接管。

需要在其他既有ROS工作区安装更新时，使用项目原ROS环境构建`mooncar_slam`；CMake会安装新节点、传输及窗口模块。例如本环境：

```bash
source /opt/ros/jazzy/setup.bash
cd /work/ros2_ws
colcon build --base-paths /source/ros2_ws/src --packages-select mooncar_slam --symlink-install
```

新模式的逐帧记录随实验保存为`window-localization.jsonl`。场景说明、模式选择和自主任务的`active_localization_revisit=false`均有记录，避免将旁路或旧方案结果混淆。

修改窗口Python模块后应重新构建安装并核对安装目录SHA；主可执行脚本是symlink，不代表CMake按目录安装的`offline_rgbd_window`包也会自动更新。本次曾因漏核此项跑到旧安装模块，旧轮独立保留，不计为修复版验证。
