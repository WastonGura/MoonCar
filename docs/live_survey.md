# 实时地形勘测

现在可以让车载记录器把带时间戳、点云和位姿的关键帧发给电脑，电脑接收后增量重建，原工作台每秒查询新结果并绘图。任务范围、质量判断、配置核对和成果导出复用[离线勘测流程](offline_survey.md)。原车辆模型、控制、导航、深度投影和地表拟合算法保持；未配置上行参数时，原记录器和档案回放照常使用。

## 不接硬件先查看

项目根目录中执行；示例与结果目录使用新目录。需要Python、NumPy及已有的web/node_modules/three。

```powershell
python scripts/offline_survey.py create-example tmp/live-example-input
python scripts/map_workbench.py --sessions tmp/map_sessions --survey-task tmp/live-example-input/task.json --live-output tmp/live-received --live-token-file tmp/live-survey.token
```

打开 http://127.0.0.1:8765/，点击左上方“查看实时勘测”。此时应该显示“等待首帧”。另开一个终端：

```powershell
python scripts/send_survey_input.py --task tmp/live-example-input/task.json --url http://127.0.0.1:8765 --token-file tmp/live-survey.token --spool tmp/live-example-uplink --interval 1
```

这是把保存的合成数据按帧发送，测试接收与绘图，不能当作新采集或实车成绩。地图和右侧质量图随收到的帧更新；示例共4帧，其中1帧在任务截止后，保留原始记录但不用于任务建图。停止发送超过5秒后，状态变为“数据已停止更新”，最后一张地图继续保留。

右侧显示任务坐标、范围、时间、暂定目标、覆盖和有效地表比例，以及缺测／拟合失败／精度未知／相对参考达标或超限。配置核对是只读的；无合格独立参考时准确度保持未知。主三维图仍可旋转、俯视和查看地形；右侧小图按整个任务范围显示缺测格，X向右、Y向上。

覆盖率仅说明收到并重建了多少区域，不设80%或其他通过门槛。新任务模板已移除覆盖目标；旧任务中的`minimum_coverage`兼容保留但不参与判断。相对参考的高程／坡度误差、未测和拟合失败继续显示；未测区域的精度保持未知。

“返回档案回放”切回原有档案查看；实时任务质量区仍明确属于接收任务，不与另一份回放档案合并。实时图不拿旧档案去执行路线对比或导航。

## 连接现有ROS记录器

数据路径为：

车载深度／内参、IMU和时间戳TF → 原有地形观测话题 → 原记录器的关键帧 → 可恢复的本地发送队列 → 电脑接收器 → 原地表重建与工作台。

传输的是原始传感器坐标点、相机到任务坐标的位姿及可用的车体位姿；投影、IMU姿态修正、自车过滤及关键帧策略没有改。不会把相机位置冒充车体位置，也不使用场景真值建图。记录器仍在本地定期保存NPZ，网络发送由独立线程处理。

在现有ROS工作区重新构建mooncar_terrain并加载环境后，记录器增加三个可选参数：

```bash
ros2 launch mooncar_terrain record_map.launch.py \
  use_sim_time:=false \
  source:='现场深度观测；设备及标定版本见任务文件' \
  uplink_url:=http://127.0.0.1:18765 \
  uplink_token_file:=/path/to/live-survey.token \
  uplink_task_file:=/path/to/survey-task.json
```

这条命令只启动记录器，不启动车辆、相机或电机。原有传感器、terrain_node、定位与TF必须已经就绪。实体采集使用系统／UTC时钟，任务time.clock写utc，起止秒为Unix时间；仿真使用use_sim_time:=true与simulation时钟。任务的坐标名、25cm格／5cm体素和来源描述必须与记录器实际设置一致，标定／位姿版本也要明确填写。参数不匹配时拒绝启动上行，不能用另一个来源标签混入旧任务。

电脑接收器与发送端使用同一份任务内容。输入路径只给离线工具使用，可以因电脑不同而不同；任务ID、坐标、范围、时间、网格、目标和来源的签名必须一致。接收器可在电脑本地读取参考与配置快照，并在任务开始时复制冻结；后续不随文件被编辑而改变判断。

如果记录器就在有ROS的电脑上运行，且已通过现有ROS网络收到车上传感器话题，uplink_url直接写电脑的http://127.0.0.1:8765即可。如果记录器在车上，使用现有SSH连接把车上本地端口转发到电脑，例如在车上运行：

```bash
ssh -N -L 18765:127.0.0.1:8765 user@WORKSTATION
```

SSH账户、连接地址和两端网络需要部署时提供；本次没有建立实车连接、安装SSH服务或开放防火墙。令牌文件由电脑首次启动接收器生成，通过已有可信文件传输方式放到发送端，勿加入仓库或发送日志。上行客户端只接受HTTP本地回环地址，跨机器数据经SSH隧道加密传输；不把带控制接口的工作台直接开放到无线网络。

## 断连、重试和恢复

- 每个接收任务有独立会话ID和从0递增的帧序号。漏了前一帧、时钟倒退／重复、坐标或版本不符时会拒绝；同序号同内容重传只返回确认，不重复融合。
- 发送端先保存队列文件，电脑先保存帧与清单，再确认收到。网络断开或确认丢失时，原帧保留并按顺序重试。不会因为网络失败阻塞原有运动控制线程；队列写入失败会报错，本地记录器仍保留该帧供后续恢复。
- 记录器的队列位于output_directory中的survey-时间.uplink。队列保存已确认帧，便于审计；上限5000帧、约500MB JSON，接收任务还限制500万原始点。达到容量会明确拒绝，需开新任务；没有自动轮换或无限期存储。
- 电脑中断后，使用相同任务与live-output重启，可从已确认清单恢复。恢复的地图先标为历史数据，直到收到新的、未重复的帧。换任务、时钟重置或重定位到另一个坐标会话时，使用新目录和新发送队列。
- 发送端重启后，可单独续传旧队列：

```bash
python scripts/send_survey_input.py --task survey-task.json --url http://127.0.0.1:18765 --token-file live-survey.token --spool /path/to/old.uplink --drain-only
```

队列或接收会话不一致时不会静默拼接。新的记录器会创建新的本地档案／队列；旧队列先完成续传，或为新一轮采集启动新任务接收器。

界面显示的是电脑“多久前收到新帧”和“最新数据在任务时钟中的时间”，两者分开。补传中的旧数据不等于车当下位置；静止时没有新关键帧也可能出现停止更新提示，它不是断言相机已故障。

## 导出与复算

右侧“导出当前成果”生成ZIP，包含收到时刻的数据前缀、原始输入副本、点云、高程DEM、网格、逐格CSV、HTML报告、来源与SHA256清单，以及task-replay.json。导出短暂锁住接收器以取得一致快照；发送端等待／重试，原帧保留。相同前缀可复用已生成的成果包。

包内live-snapshot.json记录接收帧数与最新数据时间，明确没有断言“整个任务已完成”。使用解压后的task-replay.json即可按离线命令复算。包内路径统一用正斜杠，方便Windows／Linux交换。接收器保留原始帧，因此也可在停止发送后直接处理：

```bash
python scripts/offline_survey.py run tmp/live-received/task.json --output tmp/live-final-result
```

随后已完成[运行中的Gazebo完整联调](../reports/LIVE_GAZEBO_SURVEY_VALIDATION_20261019.md)：固定镜像中8包构建与41项ROS环境软件检查通过，运行车辆的新采集共20帧全部传回；转向、暂停、接收端中断与补传、Windows界面及跨系统复算得到验证。全部工况已执行，但首次前进被原定位时间守护取消，停机有异常，未全项通过。覆盖30.05%只作统计；按当前v1.2规则，已测部分的几何精度检查通过。原v1.1证据不改写，新规则复核另存。事后真值评价不输入在线建图；简单平滑地表的局部误差不能替代实物精度。

当前是关键帧逐帧上行、浏览器约1秒查询一次结果，不是视频帧率或硬实时保证。只处理一次有限任务、固定坐标和单层地表；不做跨会话自动配准、闭环历史点云修正、无线带宽调度或长任务分块。车上算力、真实无线断连／带宽／端到端延迟和实体测量精度，仍需硬件验收；本轮有限Gazebo联调不替代这些验收。
