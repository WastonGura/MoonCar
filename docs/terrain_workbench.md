## 地图是什么

深度图 + 相机内参 + 时间戳 TF → 原始观测档案 → 三维体素点云 / 2.5D 高程 → 地形搜索。
旧 PGM/YAML 是二维占据栅格；验收 JSON 是结果记录。本轮 NPZ 才包含可重建的三维观测，PLY 为点云交换格式。
不从二维图推造高度，不使用 Gazebo 场景网格或真值作为建图输入。

首份采集在 SLAM 建图运行中取得 37 帧、6010 个体素点、255 个有效高程格。
进一步巡航采集使用已保存二维地图上的 AMCL/融合定位，最终得到 181 帧、40278 个体素点、2193 个高程格，其中 1722 格有效。
观测点记录与车体位姿均为 181 份；档案在 `reports/evidence/terrain-workbench/gazebo-survey/`。
这不是联合优化的三维 SLAM：位姿误差会进入累计点云，尚不支持历史点云随 SLAM 闭环重定位。

关键帧默认前 3 帧保留，之后平移至少 0.05 m 或转动至少 5 度才记录，避免静止时堆积重复观测。
读取使用同一已打开文件的原子快照，保存更新不会混读两个版本。v1 兼容，但缺少车体位姿时只标记相机轨迹。
高程每个 XY 格只保留一层，无法表示多层道路。支持度是采样质量评分，不是安全概率；几何不能识别松沙承载力。

离线回放支持 0.5×、1×、1.5×、2×、4×，1× 按每 350 ms 一份关键帧推进，不是按原始时间戳播放的视频。进入页面自动恢复上次选择的档案并将所有帧预存到浏览器 Cache Storage，无需先点击播放；无有效历史选择时使用列表最后一份档案。进度条灰色显示实际已缓存区段，并标注百分比；未缓存空隙不会涂满。

显示“回放缓存已就绪”后，拖动按动画帧刷新，从本地读数据，不再逐帧请求服务器。刷新页面会检查档案版本并复用缓存；跟随采集模式绕过离线缓存。当前档案缓存上限 512 MB，内存只保留最近 8 个解码帧，准备期间让交互读取优先，播放间隙继续缓存。181 帧档案本次完整缓存为 339,048,342 字节，包含空白第 0 帧；不会提前显示后续观测。

首次准备、浏览器缓存被清理或超出容量时，仍需等待计算或按需回放。后端保留增量融合、地表拟合复用与最近 4 个快照缓存作为按需读取路径。2026-09-10 两轮修复分别见 `reports/evidence/terrain-workbench/replay-performance-20260910.md` 和 `replay-cache-20260910.md`。

## 寻路研究与执行

状态为 XY 和八个离散朝向；动作是前进与原地转弯。整段检查矩形车体覆盖、未知区域、纵倾/侧倾、高差和粗糙度。
相同安全约束下比较 geometry、fixed、direction、uncertainty、full，不能跨模式直接比较不同定义的总 cost。
研究目标是路线选择，地形动态调速未实现；当前速度仍由现有 Nav2 控制器管理。

独立 `/mooncar/compute_terrain_path` 使用 Nav2 `ComputePathToPose`；网关将直线交给 `FollowPath`，原地转弯交给 `Spin`。
保留原 NavFn 作为 M6 基线，未替换默认导航配置。网页只提交目标/取消，不发布电机命令。
仿真车体包络 0.86 × 0.72 m；规划额外预留每侧 0.15 m 跟踪余量，运行监控检查原包络。
该余量来自本轮边界贴行问题，仍需针对真实定位误差、控制误差和车辆重新标定。
离线默认 0.55 × 0.45 m 是实物设计目标，不是当前仿真尺寸；启用 ROS 时网页对照使用运行规划包络。

运动须显式启用 `require_workbench:=true`。浏览器 3 秒续租超时撤销许可，安全中继另检查 1 秒许可和 0.5 秒指令真实时间超时。
运行中每秒重读地形和全局代价图，路径失效先撤销许可、确认 Nav2 取消，再重规划，最多 3 次。
当前车体区域不安全、定位/代价图过期或无路径时停止；取消无法确认则锁定新任务。
平移采样间隔不大于四分之一格，转向不大于 7.5 度，不能当作连续碰撞证明或实体安全认证。

## 验证证据

- `software-final.log`：8 个 ROS 包构建、35 项 Python 测试和 C11 核心检查通过。覆盖融合/存取/损坏拒绝、未知/退化、精确终点、方向及支持度、HTTP 输入与 Origin、真实 ROS Action 和安全逻辑。
- `synthetic-benchmark-final.json`：25 组数学地形符合预期。低支持度区域 fixed 3.25 m、full 3.871 m；圆丘 fixed 4.078 m、full 4.371 m。路径变长不是提升证明，预测纵倾/侧倾不是实测姿态。
- `gazebo-survey/recording-check.json`：真实深度观测、时间戳 TF、保存/重载/PLY；未用真值建图。
- `navigation-ui-01-check.json`：网页目标真值误差 0.08288 m，到达后安全命令为零。
- `navigation-cancel-01-check.json`、`navigation-disconnect-01-check.json`：实际浏览器取消、执行中刷新丢失租约后停止，分别观察到 41、11 个零安全指令样本。
- `navigation-replan-07.json`：已开始绕行，但跟踪偏差触发保护，失败后 41 个安全命令均为零。之后加入规划跟踪余量。
- `navigation-replan-09.json` 及 check：新增 0.2 m 障碍触发重规划，无路径则终止，16 个安全命令均为零。不能声称成功动态绕行。
- 原 M6 `m6-01.json`：关节约 24.855 Hz（仿真时间），激光/深度、禁行区和新障碍重规划通过，两个目标真值误差 0.07578 / 0.08338 m。
- 真实浏览器另检查离线回放、合成档案更新、实时采集档案更新、点选及 390 px 宽度。`gazebo-observed-map.png` 为真实深度观测图；历史截图保留来源日期。

同图同目标 fixed/full 运行对照见 `runtime-comparison.json`。墙钟耗时受 Docker/渲染负载影响；当前样本用于验收执行链路，不能证明提升成功率、减少翻车或沙土性能。
后续研究应补充充分观测的动态绕行场景、多起终点重复实验和真实 IMU/电流/打滑数据。
