# 默认定位恢复事件：旧观测到期触发，非本次匹配失败

这次停车的直接触发过程已查明：默认RGBD节点处理248.0秒曝光时，上一份247.9秒曝光结果的年龄超过0.3仿真秒，健康策略清零成功计数；新结果随后成功，但需连续3次成功才恢复。验证程序已在恢复期按原规则停车。本次没有改代码、扩大阈值、重开容器或新跑世界。

## 核查和复现

247.9–248.2区间的bag中，RGB和深度均有4个预期100ms曝光，IMU有31个预期10ms采样，无缺时间戳。默认节点也实际收到并成功处理相关帧。248.0帧有80个内点、残差约0.416mm，相关拒绝和结果失效计数没有增加；这次健康下降不由本帧特征断链、匹配拒绝或5cm不确定性限制触发。上述结论仅针对这次事件，不否认本轮其他时段已记录的IMU超时或旁路缺失。

用未修改的`LaserQualitySource`和录到的时间点做纯策略复现，得到`stale/计数0 → recovering/1 → recovering/2 → healthy/3`，与bag一致。没有仿真或定位算法重放，也未改变门限。34份受保护产品源码均与实验协议SHA一致；测试容器保持停止。

两处源码共同解释恢复状态：`LaserQualitySource.snapshot()`在旧接受观测超过0.3秒时清零；`observe()`要求3次连续成功才重新就绪。默认节点在计算期间仍会定时发布健康状态，结束后也先检查旧状态再接受新结果。即使改变结束处调用顺序，计算期间已经发生的旧观测过期也不能因此消失，因此不能简单归结为调换两行代码即可完整修复。
