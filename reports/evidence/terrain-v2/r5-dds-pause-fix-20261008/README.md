## 剩余失败及证据

IMU 在 **29.75～29.90 秒**有 0.15 秒缺口；安全速度回调时钟在 **29.718～29.94 秒**有 0.222 秒跳变，超过 0.1 秒门槛。它们位于暂停交界，两个相邻回调的接收墙钟差分别约 0.621、0.626 秒。其他最大内部间隔分别为 0.01 和约 0.06 秒。

测试主线程在此处同步执行 `gz service` 和 `gz topic` 子进程等待，没有持续调用 ROS executor。代码行为与上述接收时间线一致，是需要修正的具体测试阻塞点。缺帧责任仍没有经独立发布/桥接接收对照完全隔离，本轮不宣称 DDS 或相机再次出现相同故障。安全速度的时间跳变也不能当作发布间隔。

接收端容量判定要求进程不得映射任何 8 MiB 段，这个条件错误：当前固定版本 `SharedMemManager.hpp` 的接收逻辑使用 buffer descriptor 的 `source_segment_id` 打开发送方段，收图进程会正常映射桥接段。记录中的远端 8 MiB 路径与桥接初始化回执中的段完全相同，其他节点加载的库及容量环境变量没有改变。加载 RMW 库但未创建 participant 的进程也不能仅凭库路径算作接收 participant。

不能仅移除错误条件后补判本轮通过，因为接收进程自有段身份尚未核验，且 IMU/速度记录已经独立失败。下一步需要区分自有发送段、远端读取映射与纯归档进程，以实际 participant 配置核验容量。

只读诊断见 `after-stop-audit.json`；正式 `result.json` 和 `campaign/ledger.json` 保留失败，`summary.json` 保存实际次数。`final-freeze-verification.json` 确认本轮冻结后执行源码及安装文件未改动。
