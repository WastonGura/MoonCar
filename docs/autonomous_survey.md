# 固定相机自主探测

## 2026-11-02：当前窗口定位模式

工作台默认`rgbd_window`已由新定位实际接管导航，任务记录`active_localization_revisit=false`，不再依赖旧RGBD主动回访。普通目标选择、地形限制、运动许可和下述短暂失效暂停恢复保留。自然V2一轮完成12动作、约11.82m路程并正常按预算收尾，详见[当前定位配置](window_localization.md)。旧`rgbd`模式仍保留原回访行为供显式复现；不能混用两者成绩。

## 2026-11-02：短暂定位失效时暂停，恢复后继续

自主任务现在会在定位短暂失效时撤销运动许可并显示“已停车，等待定位恢复”。任务时间预算继续计时；旧动作确认结束、同一定位会话重新健康且导航/传感器就绪后，普通观察动作会重新申请许可，继续原目标。手动停止后不再自动启动。等待最多15墙秒是防止任务永久挂起的操作超时，不是定位性能目标；长期断流、定位会话改变或不可恢复故障仍会结束任务并保留数据。定位有效期、3帧就绪条件、底层停车和原回访事务规则均未放宽。

V2受控用例已验证行驶途中短暂停止定位进程后，实际停车、恢复并完成后续移动/转向/扫描与地图归档。该用例使用固定观察路线和明确故障注入，不代表自然全场探测已经验收。两墙秒停止进程的另一个用例超过原定位核心一仿真秒断流限制，未恢复，按保护规则结束；此记录保留。详见[暂停续跑验证](../reports/SURVEY_PAUSE_RESUME_V2_20261102.md)。

## 2026-10-06：限次重新观测与重规划

新任务记录执行规则 `bounded-recovery-v1`。三个候选动作失败后，v3 策略最多尝试一次原地云台重新观测（水平 +90°、俯仰约 -15°），随后从新观测重新选择正常候选。恢复扫描不计预测收益，不移动底盘；失败目标的历史排除继续保留。正常原地扫描成功不会清除导航失败计数，正常移动成功才清除；一次恢复成功可开始下一组尝试，但整个任务只有一次恢复机会。再次累计三个失败、无云台接口或恢复失败时结束为 `fault`。v1/v2 不执行恢复扫描，三个失败后停止。

扫描必须通过原来的定位、传感器、地图新鲜度、活动半径、心跳和硬截止检查，并在原时间预算内预留约 8.14 秒动作估计加 4 秒执行余量。扫描后必须取得比开始前更多的记录关键帧，否则保留失败动作并停止。`recovery`、触发失败次数、恢复次数及错误写入任务记录，自动归档保留这些字段。成功扫描不证明已脱困，也不证明 Nav2 能执行下一个目标。

同时修复云台目标视向与底盘朝向一致时漏发扫描命令的问题：云台动作根据 `use_pan_tilt` 执行，不能只比较车头朝向差值。

离线回归入口（已有 Python/NumPy 环境，无需 ROS）：

```bash
python scripts/check_survey_planner.py --report reports/evidence/terrain-workbench/bounded-recovery-20261006/offline-tests.json
```

本次 35 项相关测试通过，详见 [验证记录](../reports/evidence/terrain-workbench/bounded-recovery-20261006/README.md)。随后已恢复 ROS/Gazebo 环境，见 [恢复记录](../reports/evidence/environment-restore-20261006/README.md)。历史冻结批次继续按各自源码解释，不能将新执行规则直接混入旧对照成绩。

云台动作完成现要求 `/joint_states` 中两个不同时间戳的反馈样本均到达目标，水平/俯仰误差各不超过 5°，反馈同时满足墙钟与仿真时间新鲜度；经过预计时间本身不再表示成功。反馈未确认到位时受仿真预算及墙钟上限约束并报告失败，运动许可保持关闭，不改用底盘旋转。诊断保存目标、实测角度、反馈年龄和到位样本数。独立闭环验收入口为 `scripts/check_survey_recovery_runtime.py`，启动方式见 [容器说明](../containers/README.md)。

实际闭环五轮及 141 项完整回归已通过，见 [运行证据](../reports/evidence/terrain-workbench/recovery-runtime-20261006/README.md)。受控轮次的导航失败及候选序列为测试夹具，实际扫描、关键帧和后续 Nav2 不替换；无注入轮仍存在导航停滞及控制器失败，任务提前按预算保护结束后继续观测至 90 秒。不能据此宣称真实脱困、全场覆盖或策略统计提升。

## 三策略统一入口

“自主探测 → 探测策略”提供三个选项，启动后锁定本轮选项，任务 JSON、manifest 和结果表均记录策略版本。

| 选项 | 版本 | 选择规则 |
| --- | --- | --- |
| 就近观察 | nearest_view_v2 | 在能带来新观测的候选中，选估计动作时间最短者 |
| 覆盖优先 | coverage_view_v2 | 新观测投影面积 / 估计动作时间 |
| 地表补采 | surface_view_v2 | （新观测投影面积 + 采样不足格子的换方向补采效用）/ 估计动作时间 |

三者共用候选车位、视场近似、Nav2、传感器与安全限制。就近观察是观察位姿基线，不是另行实现的经典 frontier 聚类算法。冻结的 `nearest_view_v1`、`coverage_view_v1`、`surface_view_v1` 和旧 `quality_view_heuristic_v1` 仅为既有记录与离线复现保留，不出现在新任务菜单。

v2 修复了54轮正式对照暴露的共同调度问题：前进候选计入 Dijkstra 路径沿途持续采集的预计视野；若一次原地转向会耗尽最后一个仍可执行的安全前进机会，则优先前进。候选统计同时记录历史重复、低收益和时间过滤数量。有正收益候选但剩余预算不足时结束状态为 `budget_reached`，只有时间充足且确实无安全正收益候选时才使用 `no_candidates`。候选阶段统一预留4仿真秒执行余量，并在动作记录写盘后、发出运动命令前再次核对剩余预算。余量只防止明显无法完成的末段动作；Nav2仍可能因实际路径或到达容差在硬截止时被安全取消并记为中断。这些规则对三种策略相同，不改变各自的排序目标。

地表补采只处理少于 6 个体素点或平面拟合 XY 支撑不足的格子，并要求候选相机落在尚未观测的方位分箱。陡面、高残差和已经有效的表面不给补采奖励。新方位每格的 0.5 权重是**未标定效用**，不是恢复概率；纯接近但没有改变方位分箱的收益尚未建模。它不直接追逐 Q 增长，也不读取离线真值标签。

新动作的 `expected_utility_m2` 是启发式效用；对应残差使用预计视场内的新增观测面积加恢复有效表面面积。Q 增量仍单独保留，不再将这两个量混为一谈。

自动重置对照入口（在现有容器内运行；会结束当前静止实验并新建档案）：

```bash
OPENBLAS_NUM_THREADS=1 python3 /source/scripts/compare_survey_strategies.py /evidence/新建结果目录
```

默认两个起点、每个起点各策略两次、每次 90 仿真秒，半径 8 米。先写实验计划再运行，起点间轮换策略顺序；每次重启 Gazebo、SLAM 和空白采集节点。实际初始观测基线保留在报告中，不能声称浮点仿真和启动时序完全一致。异常和中断保留，不凭结束状态过滤样本。

批量对照固定关闭 Gazebo GUI 和异步现场截图，只运行相同的仿真服务端、传感器、SLAM、Nav2、策略与同步原始深度记录，以避免软件渲染占用 CPU。交互工作台任务仍默认开启 GUI；批量结果使用同步地图和评价图作为证据。

## 使用

打开现有 Windows 工作台 `http://127.0.0.1:8765/`。已有运行中的车辆时，填写时间预算（15～1800 仿真秒）与距起点最远距离（2～25 米），点击“从当前位置自主探测”。不需要画矩形，不会重置车位。没有运行中的车辆时，先展开“仿真实验设置”应用起点并采集。

后端选择前进、转向或换位补采。右侧显示原因与上一动作实际采样质量增量；目标箭头表示下一观察朝向，虚线圆表示活动距离限制。刷新或关闭网页不会取消自主任务，请保留服务进程。提前结束用“停止自主探测”；旧的手动导航仍要求网页连接。

勾选“采样质量热力图”显示灰阶充分度，点击有效地表查看百分比、格内覆盖与观察方向数。关闭图层后恢复高程着色。无法可靠表达为单层地表的格子不绘制成平整地面。

## 质量与预测模型

每个 0.25 米地表格分为 4×4 子格，统计观测覆盖比例 C；从格子指向相机位置的方位分成 8 个方向，已出现方向数为 V。

`Q = C × (0.7 + 0.3 × min(V / 3, 1))`

Q 显示为 0～100%，重复相同观测不会无限增加。旧档案与回放从已有原始观测和时间对应的相机位姿重建统计，缓存版本已更新。它是**采样充分度**，不是测量准确率、安全概率或整个未知环境的完成率。真实粗糙度不直接扣减此分数；定位协方差、深度误差标定与回环后的历史修正尚未纳入。

决策只读取导航代价地图、深度采样统计和定位，不读取 Gazebo 世界几何或真值。比较当前位置和周围 1.5 / 3 米的可达位置及多个朝向。有限距离搜索估计行驶代价，Nav2 验证实际路径与碰撞；先排除危险或未知车位，不允许信息收益抵消安全限制。

按固定相机约 60° 水平视场、车头偏移和名义地面观察距离预测可见格子，射线遇到已知障碍或未知导航格终止。v2 的前进收益取沿预计路径和终点视野的并集；预期收益为新地表面积加上已有格子的补采收益，再除以估计行驶、转向和观察时间。当前位置的候选调用 Nav2 Spin，其余调用 NavigateToPose，抵达后视需要转向观察，再更新下一动作。最近尝试过的位置/朝向暂不重复。

新任务使用 survey-metrics-v1：按固定活动范围统计实际增量，并额外在候选预计可见格子内比较预测与实际质量收益。每次自主任务自动保存原始观测、开始基线、全部动作（含中断）、现场截图、黑白图表和 CSV 汇总，见 [评价与归档说明](survey_evaluation.md)。旧版没有 metrics_version 的动作仍使用全档案增量，不能直接混用。收益不是测量误差。第一版使用平面遮挡近似、固定候选距离和启发式评分，无训练模型；高物体、坡面、漂移及有限候选集合可能造成预测偏差或提前结束，尚不宣称最优。

## 结束与保护

预算使用 ROS 仿真时间，另有一小时墙钟上限。候选与执行受活动距离限制，并保留场地边界、定位/传感器有效性、地图新鲜度、Nav2 碰撞预测和运动许可中继。自主线程通过内部短租约驱动动作，线程无法维持心跳时仍会停车。

自主期间拒绝插入手动目标。预算用尽、人工停止、活动距离限制、数据失效、连续执行失败或没有安全正收益候选时结束。新的实验会先停止自主任务。采集档案与 `autonomy-*.json` 决策记录保留。

“没有候选位置”不等于整个环境探测完毕；当前没有返回起点功能，也没有全场覆盖保证。硬件验收状态不变。
