# 激光定位候选的设计与使用

本页的旧 `ekf` 仿真研究候选仍非默认，须显式选择。原车辆、土壤／接触、控制、EKF配置和此前SLAM扫描筛选修复保留。验收记录见`reports/evidence/laser-localization-20261020`；任何单轮通过均不等于实车认证。

**本页说明旧 `ekf` 候选：验收失败，保留供研究复核。** 原工况和三个新工况均未通过全部标准，左转120°时有效匹配中断后出现明显估计漂移。结果见[完整报告](../reports/LASER_LOCALIZATION_CANDIDATE_VALIDATION_20261020.md)。

后续新增了独立的 [`direct` 局部激光定位模式](local_metric_localization.md)，修复法向支持尺度、失配后位置外推、重复地图修正及质量发布时序。它的启动方式、适用边界和最新验收见该说明与[定位修复报告](../reports/LOCALIZATION_REPAIR_20261020.md)；下文旧 EKF 候选的结果不代表新模式。

2026-10-20 后续增加了候选专用的定位质量联锁，见[联锁验证](../reports/LOCALIZATION_QUALITY_INTERLOCK_20261020.md)。它阻止失配期间继续运动和融合新深度帧；未修正匹配算法或 EKF 漂移，也不代表原定位精度验收通过。

## 定位链

水平激光＋同步IMU朝向＋轮速预测 → 激光估计的车体XY位置 → 候选EKF → 原SLAM及导航／采集。激光节点只发布里程计和状态，不发布TF；EKF继续唯一发布odom→base_footprint。SLAM维持地图坐标校正，采集、传输和地形重建路径不变。

本次实现采用带IMU朝向先验的稳健点到线匹配，不是RF2O包的直接移植。RF2O是调研候选，其现有ROS2封装的横向速度、协方差和初始化需要适配，本次未直接安装使用。点到线匹配方法可参考[Censi的PLICP论文](https://censi.science/pub/research/2008-icra-plicp.pdf)；本项目仅优化平移，属于自己的受限实现，不宣称复现原论文性能。

固定安装变换从base_footprint到激光和IMU的TF读取。先把雷达偏置及IMU安装方向换算到车体，避免把雷达绕车体的运动冒充车体平移。算法不读取Gazebo真值、SLAM位姿或地图修正量；世界／地图初始同轴约定不做事后拟合。

有效回波、匹配数量、方向可观性、残差和突变均有检查。匹配失败时不把轮速预测包装成成功的激光测量。参考子图最多20个关键帧；每次匹配最多12次迭代。移动中逐帧定位，停止后快速校正最多1秒，之后用新扫描最多每0.2秒维护一次位置，匹配原EKF的sensor_timeout=0.2秒；静止维护不插入参考关键帧。上一版仅1Hz维护导致预测间隙过长，已保留其失败记录。

候选配置不再融合轮速消息里未测得的vy=0，而融合激光XY位置。激光使用IMU朝向作先验，所以不把同一朝向再作为独立激光yaw融合。协方差有保守正定下限，不用零协方差表示绝对准确。横向速度输出由连续有效车体位姿计算，候选EKF只融合激光XY，不重复融合由同一位置求出的速度。

## 开关

原`terrain_navigation.launch.py`启动命令可增加：

```text
online_mapping:=true laser_odometry:=true laser_odometry_mode:=ekf
```

复核这个旧候选时，工作台服务环境须显式设置`MOONCAR_LASER_ODOMETRY=true`和`MOONCAR_LASER_ODOMETRY_MODE=ekf`。当前未设置变量的在线勘测默认选择新direct模式，见[当前说明](local_metric_localization.md)。在线勘测中，显式`laser_odometry:=false`可选择原`ekf.yaml`并关闭激光节点；旧激光EKF候选选择`ekf_laser_candidate.yaml`，原文件不改。

需要先按原流程构建并加载mooncar_slam、mooncar_control、mooncar_terrain和mooncar_navigation。启动时保持车辆静止，等待激光节点质量状态healthy=true；initialized=true仅表示已有参考子图，不能作为动作就绪条件。初始化之后连续三次真实有效匹配才开放联锁，初始化原点消息本身不计入这三次。初始化期间移动会锁定故障，需开启新会话，不能把已经移动后的位置悄悄当成原点。

`/mooncar/laser_odometry/status`包含输入／接受／拒绝计数、初始化状态和最大匹配耗时，并新增schema_version、session_id、sequence、stamp、accepted_stamp、ready_since_stamp、healthy、reason和successful_streak。它每0.1墙秒发布心跳，真实拒绝时立即发布失效。扫描与IMU、轮速需要时间戳包围插值，禁止用陈旧数据外推。长时间扫描间隔或时间倒退不会自动重设坐标原点。

## 候选质量联锁

`laser_odometry:=true`会同时启用独立速度安全中继和地形处理节点的`require_laser_localization`。工作台环境变量仅接受`true`／`false`，并把相同选择传给工作台运动控制和记录器。当前顶层在线勘测默认启用这条联锁；底层独立节点及离线入口仍保留false，独立启动记录器时应同时设置`require_laser_localization:=true`。原定位回退方案不需要质量发布者。

任一真实失配、同步失败、非法输入或缺失状态会关断许可。有效位置测量最长允许0.3仿真秒，状态收取最长允许0.5墙秒；允许至多0.1仿真秒的消息时钟先后误差。静止时的stationary_hold是正常限频，但不能刷新有效测量时间。暂停仿真时仍须保有墙钟心跳。状态序号倒退／重放或格式错误不会刷新接收时间；生产者会话改变或仿真时钟倒退需要显式开启新实验。

失效后速度中继立即清空旧命令，并通过原20Hz独立墙钟检查持续发送零速度；恢复需要三次新的有效匹配，恢复后只接收新速度命令。工作台会取消正在执行的动作，质量恢复不会自动重启该动作。恢复纪元改变即使中间的失效消息丢失，也会触发关断。地形处理和记录器丢弃待处理帧，既有地图保留；恢复后仅允许当前健康纪元内、时间不晚于最近有效激光测量0.1秒的深度帧。状态失联后的本地恢复同样需要新的测量并建立新采集纪元，不能补入失效期间积压帧。

联锁没有给EKF虚构位置或零横向速度，也没有修改原5秒目标确认、TF时间容差、车辆／土壤接触、SLAM、传感器或精度门槛。它的作用是阻止继续使用已知失效的数据；被匹配器接受但仍有偏差的估计，仍须通过独立真值验证。

## 验证边界

独立测试和报告必须同时记录转向末XY误差、静止期P95、静止位置波动、全阶段误差和数据完整性。原3cm位置、1cm静止波动门槛以及5秒目标确认等保护不因候选而放宽；覆盖仅统计。离线原工况参与了方案选择，只有冻结后的新工况可作为未参与选择的验证。

当前使用二维水平扫描。车体倾斜超过原水平过滤器门槛时会缺少合格扫描；本轮平地转向、远观坡面建图不证明在坡上行驶时定位有效。大倾角、弱特征／动态物体、激光持续失效后的融合退化处理、长任务、非零出生航向坐标约定和实物标定仍需专项验证。联锁的软件检查和既有记录回放不等于新Gazebo闭环停车试验，更不等于实车制动距离验收；本页旧 `ekf` 候选仍非默认。

软件检查：

```bash
cd ros2_ws/src/mooncar_slam/tests
python3 -m unittest test_laser_odometry
```

检查覆盖侧向位移可观测性、雷达安装偏置、单墙退化、缺失／重复／间隔过大数据、失配后预测恢复、初始化移动、正定协方差及有界静止维护。
