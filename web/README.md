路径从实际起点开始，含检查后的终点连接和显式原地转弯。规划坐标精确不代表实车到达精度。

首次准备时仍可操作，后台准备在前台读取期间让出资源，播放间隙继续推进。跟随采集模式绕过离线缓存，关闭后恢复缓存准备。

回放支持 0.5×、1×、1.5×、2×、4×；1× 每 350 ms 展示一个关键帧，可在播放中切换，下一次调度使用新倍速。没有对观测或车辆位姿做视频插值；帧数位置只显示数字，不反复切换载入提示。
5000 帧/500 万原始点为档案显式容量上限；大场景需拆分或分块，完整 JSON 回放缓存适用于小规模离线展示。

## 网页设置实际仿真起点（2026-09-10 基线，后续更新见文末）

当前 Windows 主机已有配置好的 Docker 容器，可直接在 PowerShell 执行：

```powershell
& 'D:\Document\Repositories\MoonCar-mapping\scripts\start_workbench.ps1'
```

服务已运行时复用并保留当前实验；服务未运行时使用已有容器启动，不安装依赖。**Windows / Chrome 使用 `http://127.0.0.1:8765/`**：网页由 Windows 本机提供，仿真控制转发到容器的 8766。PowerShell 窗口作为前端服务运行时需保持打开。

已有依赖并已构建 ROS 工作区时，在 Ubuntu 的项目根目录启动：

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
python3 scripts/map_workbench.py --sessions tmp/experiment_sessions --simulation --port 8766
```

浏览器打开 `http://127.0.0.1:8766/`。此命令要求已有 Gazebo、Nav2、xvfb-run、NumPy 和本地 Three.js；不会自动安装。
独立虚拟机默认只能从虚拟机内浏览器访问；宿主机可使用自行建立的 SSH 本地端口转发，不要直接把控制端口暴露到局域网。

1. 展开“仿真实验设置”。点击“拖动画区域”，按住左键拖出矩形，松开完成；也可输入坐标。绘制期间滚轮继续缩放、右键继续平移，进入绘制不会强制改变视角；Esc 取消当前绘制。
2. 点击“放置车辆”，先点实际出生位置，再点车头前进方向。也可输入 X、Y、朝向；0° 为 +X，90° 为 +Y，Esc 取消选点。
3. 点击“应用起点并采集”：结束本服务拥有的旧实验，使用同一组位置、朝向初始化 Gazebo 车体和 AMCL，再启动全新的记录器。
4. 收到传感器档案后，页面自动切换到新记录并跟随更新。“结束当前实验”结束本服务拥有的仿真，保留档案。
5. “保存任务 / 载入任务”处理小型 JSON 配置；该文件保存区域与起点，不是地图观测档案。草稿刷新后自动恢复，载入草稿不会自动移动或重启车辆。
6. 等待导航、定位与传感器就绪后，在“导航采集”输入目标坐标或点选目标，点击“开始导航并采集”。Nav2 到达目标后停止，沿途采集保存在同一份档案。
7. “停止移动”取消当前导航；“结束当前实验”关闭整个仿真。页面心跳中断约 0.9 秒会撤销运动许可并取消导航；仍保留原安全中继的地形检查和指令超时。

页面并排显示实际 Gazebo GUI 画面（约 2 帧/秒）与传感器观测生成的地图。GUI 在容器已有 Xvfb 显示器中运行，Pillow 仅截取该虚拟显示器；现场图像不参与建图。地图档案默认每 5 秒**仿真时间**保存，实际墙钟刷新间隔随仿真速度变化。相机和定位正常时，静止不增加重复关键帧，页面明确显示此状态。

每次应用会建立 `experiment-<id>/task.json`、`simulation.log` 和 `survey-*.npz`。结束旧仿真后才创建新实验；记录器、仿真时钟和定位一同重启，旧档案不覆写。
仿真子进程使用 ROS_DOMAIN_ID=89，每份实验使用独立 GZ_PARTITION；同一机器不要另起使用该 ROS domain 的仿真或控制程序。
服务退出会结束其子仿真；重新启动服务不会自动恢复或运行历史任务。

当前限制：仅支持 lunar_yard 矩形区域与平地起点，坐标为场景/map 平面米制坐标，范围 -20 至 20 米，每边至少 0.5 米。起点检查使用当前场景碰撞几何的保守外包围框，拒绝车体与障碍或坡面重叠；场景数据只用于出生检查，不写入观测地图。
AMCL 仍使用已有二维定位地图；选点不代表任意地点都能可靠定位，120 秒无档案会提示检查。深度传感器有视野限制，车辆静止时通常只有最初几个关键帧，此后档案不更新是可能的。
**当前支持用户指定目标的 Nav2 导航采集，尚未生成整块区域的覆盖路线或实现三种自主探测策略。** 区域用于检查起终点车体包络，并在车辆接近边界时停车；导航规划器尚未把区域边界作为全局代价地图约束，因此绕行途中接近边界可能停止。原有“路线设置”依旧是离线研究规划对照，本轮演示使用现有 Nav2 导航，不冒称新的探索算法。

`--simulation` 是 Ubuntu / 容器拥有仿真的模式；`--simulation-url http://127.0.0.1:8766` 是 Windows 前端连接容器的模式；`--ros-archive` 是原有研究规划器执行模式，三者互斥。

2026-09-11 连通性与运动验收：Chrome 实际打开 8765；绘制过程中滚轮缩放并左键拖出区域成功。车辆从 (3.5, 3.0) 行驶到 Nav2 目标 (4.8, 3.0) 附近，Gazebo 真值约 (4.737, 2.982)，关键帧 3→20、体素点 970→6230、有效地表格 28→331。手动停车与故意不续租后的停车均实跑通过。详见 `reports/evidence/terrain-workbench/live-demo-20260911/README.md`。

本轮真实 Gazebo 检查：两组起点 `(0.5, 0, 0°)` 与 `(3.5, 3, 90°)` 与车体位姿一致；切换及结束后旧进程无残留；石块内部起点被拒绝而当前实验继续。证据见 `reports/evidence/terrain-workbench/experiment-setup-20260910/README.md`。

## Windows 独立 Gazebo 窗口（WSLg，2026-09-12）

先按上文启动前端，在网页点击“应用起点并采集”。然后在另一个 PowerShell 7 窗口执行：

```powershell
& 'D:\Document\Repositories\MoonCar-mapping\scripts\open_gazebo.ps1'
```

Windows 会出现 `Gazebo Sim (docker-desktop)` 窗口。它通过已有 WSLg 显示接口运行 `gz sim -g`，连接当前实验的同一个 Gazebo 服务；不启动第二辆车或第二套导航。网页的现场截图和采集地图仍可同时使用。Gazebo 场景的默认操作为左键拖动平移、中键拖动旋转、滚轮缩放。

关闭该窗口只退出独立 GUI，采集继续；停车和结束实验仍使用网页按钮。网页应用新的起点后，需要重新执行此命令连接新实验；重复执行同一实验时复用已有窗口。脚本仅替换带有自身标记的临时 GUI 容器，保留后端和档案。

此入口适用于当前 Windows Docker Desktop、Ubuntu WSL 2 与已有 `mooncar-terrain:jazzy` 镜像，使用 Docker Desktop 暴露的 WSLg X11 socket 路径。不安装依赖、不拉取镜像、不修改系统显示或网络设置。继续使用原有软件渲染，未验证 GPU 加速性能；WSLg 本身可交互不代表复杂场景的帧率已通过验收。

现场检查命令（需已开始采集）：`pwsh -NoProfile -File scripts/check_wslg.ps1`。它检查 GUI 复用、实验不变、传感器活跃及 Windows 前端连通；鼠标交互需另行在真实窗口验证。

## 50×50 米场地、在线导航地图与路径显示（2026-09-12）

新建网页实验现在使用 50×50 米场地（X/Y 为 -25～25 米），保留中央地形并增加 32 处分散的石块、坡台和山脊。场景由 `survey_world()` 生成到每份实验的 `survey_yard.sdf`，只用于仿真和出生碰撞检查，不能当作采集成果。原始 `lunar_yard.sdf`、静态地图及旧档案保留。

“选择 50×50 米全场”更新任务草稿；“应用起点并采集”新建静止车辆与记录器；“开始导航并采集”执行用户给定目标。没有实现整场自动覆盖或自主选择下一个探测点。

新实验使用 SLAM Toolbox 在线激光建图及定位，替代 AMCL 和固定 map_server，Nav2 地图随观测更新。`survey_odom → odom` 只表达用户设置的起点坐标和朝向，后续运动依赖轮式里程计、IMU 和激光匹配，不读取 Gazebo 真值定位。`online_mapping` 在通用导航 launch 中默认关闭，原 M6 静态导航入口保留。在线导航栅格为 0.10 米；深度地表仍为 0.25 米。

导航图把有效的激光正无穷读数作为量程内无障碍观测进行射线清除（`inf_is_valid`），不把 NaN、地图之外或遮挡后的未知区域填成自由空间。目标越界、未知或落入致命障碍/车体余量区域时拒绝，保留 Nav2 碰撞检测与地形安全中继。要去更远处，应先去已观测边缘，地图扩大后再选下一个目标。

实时页面现在显示实际 `/plan` 路径、目标圆环、执行中车辆位姿采样形成的轨迹和剩余距离，Nav2 重规划后更新线路。“查看导航全貌”把路径和目标纳入视野。浅灰底图是导航代价地图的已知区域，深色包括障碍与安全余量；它不是深度相机已采集完整的地表。深度点云与地表继续来自原有观测档案。离线回放或切换旧档案时隐藏当前导航叠加层；任务结束后标记为最后一次路径。

此前 `(0.23,-2.80) → (5.30,-0.31)` 的日志先报告碰撞风险、控制器等待超限，再被网页固定 180 秒墙钟预算取消。新网页位置目标使用 PositionGoalChecker（0.15 米），不强制到达后的终点朝向；Nav2 的路径有效性、碰撞检查、进展检查均保留。总预算改为按距离估计的 120～900 秒仿真时间，另有一小时墙钟上限；页面失联、传感器过期仍按墙钟立即触发保护。界面保留具体错误码/原因，任务结束时清除“正在采集行驶”的旧提示。

限制：扩展场地不等于已完成 2500 平方米采集，未知区域仍为空。在线 SLAM 的历史深度档案没有回环后重新融合，长距离运行仍需评估累计误差与闭环一致性。新增 32 处几何复用现有仿真形状，不代表真实沙土物性或实物车性能；整个场地的导航成功率尚不能由单条路线证明。
