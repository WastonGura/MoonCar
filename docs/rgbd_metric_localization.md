# RGBD 米制定位实验后端

2026-11-02：本文以下描述旧`rgbd`后端。工作台当前默认已切换为[多关键帧窗口定位`rgbd_window`](window_localization.md)，由新方案实际提供导航位姿并关闭旧主动回访。旧模式仅用于显式选择和历史复现。

`laser_odometry_mode:=rgbd` 是原生 Terrain V2 无标柱场景的实验后端，现已设为工作台、容器及在线地形启动的源码默认。服务在启动时固定选择；已有服务须先结束实验、重启，再新建实验使用新默认，实际后端以启动参数和采集档案为准。不能从页面仍显示的“激光定位”通用质量字段推断传感器来源。显式 direct／terrain／EKF 回退及离线入口保留，全场、长时、坡面和实车尚未完成验收。

## 输入与输出

定位输入仅为同曝光、已配准的真实 RGB 与米制深度、两路完整且一致的 CameraInfo、曝光时间的相机安装／云台 TF，以及可在该时刻插值的完整 IMU 姿态。轮速只提供搜索初值；初始化后缺少轮速时，仍须由新的 RGBD 测量决定位置。世界真值、地形模型、占据地图、控制目标及指令位置不参与定位。

`rgbd_v1` 仿真传感器配置在原车型相机安装位置使用一个 Gazebo RGBD 传感器，保持 320×240、10Hz 和原有光学参数。同曝光 RGB、深度及标定分别桥接至 `/mooncar/localization_rgb/{image,camera_info}` 与 `/mooncar/depth/{image,camera_info}`。RGB 图像中的纹理来自原始场景；不追加定位标柱、地面纹理或其他定位设施。`survey_v2_native` 使用原始 V2 地形；`survey_v2` 仍是保留四根标柱的兼容场景。

RGBD 仿真入口为图像和 CameraInfo 显式使用可靠传输、深度为 2 的队列；独立节点默认保持原 best-effort 深度 5，必须与实际发布端匹配。图像按曝光时间精确配对，不以接收时间假装同步。一个计算线程加一个可替换的待处理曝光限制积压；丢弃旧曝光不会刷新定位质量。计算前后均检查真实测量年龄、状态年龄、标定代次和时钟。

节点是该模式唯一的 `odom → base_footprint` 动态发布者。测得的 XYZ 与 IMU 朝向用于 TF 和里程计输出；已知实验起点通过声明的静态设置变换进入地图坐标，评价时不做轨迹拟合。RGBD 模式关闭二维 SLAM 的二次位置修正。

## 匹配与失效条件

仅处理真实 RGB 对比度后提取 ORB 特征，通过唯一、双向描述子对应建立身份，同像素米制深度提供三维尺度。IMU 已给出旋转，三维注册估计平移。参考包含起始锚点和有上限的已注册测量；参考维护不能替代新曝光的真实对应与注册。

真实身份由原 ORB 匹配和原始种子像素的密度筛选一次确定。随后可在已有 CLAHE 灰度图中，用固定亮度模型的双向局部 LK 精化这些身份的当前像素位置：窗口为 21×21，单层、带原 ORB 初值，两端均须通过 OpenCV 的模板梯度检查，返回误差不超过原 0.5px 下限，位移不超过双方 ORB 尺度的原三倍合成噪声预算。最终实际图像窗口及其余量须在图内，独立双线性采样得到的前向均方光度误差不得增加。无法精化的身份继续使用原测量，不按注册残差删点。

精化位置从真实深度网格双线性取点，沿用原 4×4 有限性、0.15m 深度连续性和局部梯度条件。局部协方差保留原 3mm 深度、0.5px 像素与 ORB 尺度下限，并使用同时覆盖原／新局部雅可比协方差的半正定上包络。完整注册、空间支撑、歧义、残差、参考维护和自身注册仍执行。每个参考使用私有测量副本；原始当前特征与已保存模板不会被精化结果覆盖。同一实际曝光仅跳过光度精化，自注册及协方差检查仍保留。

这些条件属于明确的工程测量模型。局部协方差上包络不能证明任意跨点或参考与当前相关误差均被覆盖，OpenCV 的内部迭代路径也不可见；只对最终采用的实际图像／深度窗口作独立域检查。当前核心通过原85项与新增9项检查，以及十二组7066帧历史和新增497帧故障记录；旧历史的非耗时结果与此前80d精确一致。这不证明在线时效、实际真值精度或完整能力通过。

参考维护同时考虑相机旋转和实测点的像素视差：把旧参考已注册的真实三维点投影到当前已接受位置的相机，按真实焦距及半个 ORB patch 的像素尺度判断视角是否已经变化。投影仅决定是否保留另一个真实参考，不能生成图像身份或接受位姿。新参考仍须由已合格曝光自验证；旧参考复用保留独立注册和锚点冲突检查。无效或在相机后方的投影不能证明“仍是同一视角”。

已接受的同一配对支撑层若接近原图像跨度边界，也可提前交接：按双方各自原始深度 ROI 换算跨度余量，余量不超过半个 ORB patch、且实测投影视差至少四分之一个 patch 时保存新参考。另在已接受 RMSE 距原 15mm 门槛只剩一个 3mm 深度下限的余量时，若实测视差超过双帧原身份对应最粗 ORB 尺度的三倍合成像素误差预算，也可提前保存。该预算使用原 0.5px 下限和双方最大尺度的平方和开方，不按内点或支撑层挑选尺度。

最新已注册参考若在本次真实跟踪中明确因注册残差超限被拒，而另一个旧参考完整合格，还可触发一次新视图交接。此时当前已接受视图相对最新参考和该成功旧参考的真实投影视差，须分别超过原双曝光尺度的三倍合成像素噪声预算；身份或空间支撑不足本身不触发此补救规则。已有参考若被独立完整注册证明处于当前像素噪声范围内，仍可复用。新增视图继续通过原自验证、锚点协方差与强测量冲突检查，失败时完整回滚。

连续完整接受的曝光若使用同一实际参考，原密度筛选后的身份对应数正在下降，且再下降同样数量会低于原24对门槛，也可提前请求交接。这只是已观测支持余量的维护信号，不是未来观测或新位姿。只有触发余量不足时，才至多额外执行一次相邻真实曝光的原始双向ORB匹配；须至少24对，且逐对实际像素位移／原双尺度三倍合成噪声预算的中位数大于1，才能证明可分辨运动。原参考到当前的累计视差不能代替相邻运动。

该趋势只约束有同参考证据的模板，其他独立合格模板保留原复用规则。若维护时改用另一真实参考，取消原趋势单独触发的新建，最终历史仅保存实际采用参考的对应数量；原本已满足的其他维护条件继续执行。历史只保留上一完整核心接受事务的私有描述子／像素／尺度小副本，拒绝、异常、关闭、标定或图像尺寸改变、非连续采样间隔均清理；正常相机姿态变化不视为标定改变。核心接受历史不代表外层节点已发布，原处理前后时效及质量联锁仍单独执行。

保存与旧视图复用使用相同条件；角度、视差、支撑余量、残差、图像新颖性和自验证覆盖基准均使用本次真实匹配成功的同一参考，不能混用旧活动参考。静止波动自身不能触发新增参考。这些维护针对已测图像支持及注册残差边界，不是所有几何或协方差边界的保证。状态中若包含 `last_fit.view_admission`，其中记录本曝光的实际维护判定，不会刷新 `accepted_stamp`。

常规跟踪最多尝试五个参考，起始锚点和最新参考保留优先位置。其余候选优先考虑上一接受视图及投影后的有效可见范围、像素位移和相机朝向，避免原地转向时被毫米级车体位置差误导；可见性同时受真实 0.1–6m 深度范围约束。排序不改变参考库内容，也不能绕过 RGB 身份或米制注册。质量状态中的 `last_fit.exposure_stamp` 是本次计算的真实曝光时间，`reference_attempts` 是实际尝试记录；二者都不会刷新 `accepted_stamp`。

仅当常规五次跟踪全部失败、且没有任何歧义拒绝时，才可尝试上一完整接受曝光的实测记录。核心至多保留一个拥有实际原始特征、深度网格、标定、曝光时间、朝向、最终位姿和完整平移协方差的未注册记录；正常成功路径不新增匹配或修改参考库。标定、时间连续性、拒绝、异常和关闭均有失效守卫。先按原完整自验证确认该过去测量可以建模，再通过原完整跨帧注册求当前位姿；自验证协方差只作资格检查，不能替代保存的真实锚点协方差。

该失败分支明确将实际跟踪上界从五次增至六次：五次原跟踪、一次过去测量自验证、一次当前至过去测量的注册、至多两次近视图强冲突检查，总完整fit仍不超过原最坏九次。它不再追加旧锚采用或当前帧自验证；所有已计算的强测量继续两两检查，只有成功后才原子提交到原20项库。`last_fit.view_admission.recent_reference_registration` 保留真实过去曝光时间、参考编号和父参考；不能把本次发布时间误当作新模板的测量时间。失败或时效联锁不会自动恢复已取消的动作。

参考库保留坐标原点、最新视图、本次实际父参考及活动视图，容量仍为 20。其余项按已测相机视野的稀疏双向覆盖和原 XY 锚点协方差淘汰冗余参考；视野评分只是保留和搜索线索，不证明图像身份或位置。先在局部候选库评分，再一次性提交不超过 20 项，状态线程不会看到未提交的第 21 项。固定旧参考之间的覆盖计算可缓存，提交后至多 190 对；淘汰、对象替换及事务回滚均清理缓存。当前曝光的动态投影仍重新计算，缓存不改变选择或接受条件。

描述子表仅在双方均为 `uint8 N×32`、行序与完整内容相等时使用等价计算：唯一行恰有一个零距离自匹配，重复行因原严格比率测试中的两个距离均为零而被拒绝；不足两行仍无对应。其余输入继续执行原双向 Hamming 匹配。排序、ROI 密度筛选、几何拟合及新参考自验证均保留。此项只减少重复计算；72 项测试及九组共 3935 帧回放的非耗时结果与此前版本一致，不能据离线耗时推断在线时效。

常规事务仅在确实需要建立新参考时，可复用本曝光已有的合格旧参考结果，或额外验证至多一个合适的旧参考。其完整身份、几何、歧义、残差和协方差检查均保留；所有强测量须两两一致。采用的是同一次真实注册的位置、协方差和参考编号，不能只替换协方差，也不融合相关性未知的结果。常规跟踪至多五次、原近视图冲突检查至多两次、新增采用检查至多一次及自验证分别计数。失败的本曝光参考不会重复占用新增检查名额。建帧推迟到同一接受事务中，结果和库一起完成；失败及回滚如实记录。

以下工程门槛在修复中保持生效：至少 24 个真实 RGB 身份对应、至少覆盖有效深度 ROI 的 6/12 个网格、两个像素轴跨度各至少 30%、三维中间特征值至少 0.0025m² 且至少为最大特征值的 2%、米制一致比例至少 55%、注册 RMSE 至多 1.5cm、预测修正至多 10cm、XY 标准差至多 5cm，并保留协方差传播和三维 3σ 歧义检查。这些是接受条件，不是实际误差的保证。

空间支撑检查采用显式的双支撑定义：完整配对内点在双方合格，或一组固定高精度配对内点在双方独立合格；不能将一帧的完整层与另一帧的高精度层拼接。高精度层使用原密度筛选后的全部真实身份对应定义，配对标准差上限为其中最佳配对的两倍，不随一致内点或 PCA 结果调整。两层各自沿用上述原始 ROI、数量、格数、跨度和米制特征值门槛。完整对应仍用于位姿、一致性、歧义、残差及协方差；不会用高精度层重拟合位置。此处改变了充分空间证据的定义，不能将其描述为判定算法完全不变。

连续三次真实接受的测量才进入就绪。接受测量年龄超过 0.3 仿真秒、状态超过 0.5 墙秒、图像身份或空间支撑不足时，质量失效。运动联锁撤销当前动作并清空旧速度；重新健康不会自动恢复旧动作。新实验时钟必须在旧发布者退出后按新代次重新绑定。

## 观察与导航

RGBD 模式由真实深度地形观测生成导航地图。未知格保持未知；历史已知格有界保存，不能用插值、射线假设或世界地形把未知格填成可通行。

三维模式的候选视野预测区分“通行性未知”和光学遮挡：对应质量格已有有限正数的真实测点时，可支持预测视野继续；遇到未观测的首个前沿或已知 100 障碍仍停止预测。该粗格支持只表示潜在观测机会，不证明光路或地面可通行。移动路径、目标代价、已知 0.65m 净空、历史和预算检查保持，实际收益仍由动作后的新测量计算。原二维模式保留此前的未知遮挡行为。

深度地图按实际观测逐步分配，因此数组边缘不代表场地边界。三维模式的既有备用候选搜索不再要求目标位于当前数组边缘 3m 范围内，已知安全的内部位置也可参与选择；仍要求目标已知、代价合格、Dijkstra 可达，并满足原净空、距离、历史和预算条件。原二维边缘过滤保留。此修复不改变未知格，也未解决自定义较小用户区域在自主选点中的传播问题。

若起点附近缺少可通行连通域，自主探测先执行有预算的原地云台观察。云台动作等待真实关节反馈，并使用 0.35rad/s 的命令斜坡；限速不替代曝光同步和定位质量检查。观察期间底盘许可关闭；每步必须取得新的档案帧和更新的地图时间戳，再检查保留 0.65m 底盘净空的实际连通目标。只有满足条件后才允许通常的 Nav2 导航。

## 验证边界

真实误差以独立 Gazebo 车体真值评估；真值仅进入评价器。所有原始真值时间戳构成可用率分母，缺少同时间 TF 的样本不能删除。事后得到的 TF 插值也不能证明在线测量及时，必须同时检查原生质量状态、动作取消和安全速度。

开发记录及失败保存在 `tmp/ros_acceptance/localization-expansion-repair-20261020/`，结论见 `reports/LOCALIZATION_EXPANSION_REPAIR_20261021.md`。局部静止、一次云台扫描或安全拒绝均不能代表全场、30 分钟移动、坡面或实车通过。Gazebo 的理想图像不覆盖真实相机噪声、配准误差、曝光变化或真实 IMU 标定。
