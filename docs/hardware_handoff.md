# 硬件交接与首次上电清单

2026-11-02补充：窗口定位已成为仿真默认，但下面的台架入口仍以轮式里程计为TF来源，尚不是窗口定位整车启动方案。用户确认硬件未齐，本阶段只做[窗口定位硬件接入准备](window_field_validation.md)，不执行真机运动；接入时必须先核对单一TF发布者、实际RGBD/IMU同步及实测外参。

本阶段交付可仿真的导航系统、地形几何原型、已通过虚拟串口测试的通信与便携 C 控制核心。
下一阶段必须具备实物，才能完成电气接线、板级 HAL、参数标定和整机性能验收。
禁止直接将仿真参数当作已验证的真机参数，也不要以软件测试代替物理急停。

## 采购前必须确认

| 项目 | 必须提供的信息 | 不确认的风险 |
| --- | --- | --- |
| 底盘与四电机 | 额定电压、堵转电流、减速比、编码器电平/每圈计数、轮径、安装尺寸 | 驱动烧毁、轮速与里程计比例错误 |
| 四路驱动 | 4 个独立通道、持续/峰值电流、热设计、PWM/方向/使能逻辑 | 双通道板一块不能独立驱动四轮；型号名称不足以选型 |
| STM32 开发板 | 完整原理图、实际型号、时钟、引脚复用、ST-Link 接口 | 4 路编码器、PWM、串口、SWD 资源冲突 |
| 计算板 | 树莓派具体型号、Ubuntu arm64 镜像、散热、电源与 USB 外设功耗 | VM 性能结果不能代替树莓派负载测试 |
| 传感器 | 雷达/相机/IMU 实际版本、通信接口、电平、安装位姿、驱动支持 | 原始数据单位、时间戳与 TF 不一致 |
| 电源与急停 | 电池化学体系/满充电压/BMS/保险丝、降压额定与瞬态能力、独立急停 | 欠压重启、短路、断连后不能可靠断能 |
| 近距离传感器 | 实际型号、最小测距、表面反射与强光实验、失效输出 | 红外不能未经标定就作为唯一防跌落手段 |

树莓派 5 官方建议 5V/5A 电源，并说明 3A 供电时 USB 外设电流受限；GPIO 是 3.3V 逻辑。
请依据实际整机功耗设计电源，不能仅凭“12V 转 5V 模块”名称接线。
来源：[Raspberry Pi 官方硬件文档](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)。

S3 官方规格中，40m 对应 70% 反射率，10% 与 2% 反射率分别为 15m、5m；环境光抗性有条件。
本次未确认候选 S3 的 IP65 依据，已撤下旧清单中的无条件断言。
来源：[SLAMTEC S3 规格](https://www.slamtec.com/en/s3/spec)。

## 板级接入顺序

1. 不接电机电源，核对原理图，建立引脚表；验证时钟、串口、ST-Link、硬件看门狗。
2. 移植 `firmware/stm32/core`，实现 UART 接收、四路编码器速度、PWM/方向、急停与电压采样适配。
3. 车轮架空，限流电源，逐轮核对方向与编码器正负号。控制核心默认不解锁。
4. 实测每输出轴一圈计数、有效轮径、轮距；小占空比起步，调四路速度环及死区。
5. 拔串口、停止上位机、停止底层控制任务、触发物理急停，分别验证停止结果；记录停止距离和时间。
6. 完成传感器驱动、时间戳、外参和 IMU 轴向校准，再接 EKF、SLAM 与 Nav2。
7. 地面低速直线/转向标定有效轮距和轮速协方差；最后进入受控沙地、碎石、坡道场地。

不提供猜测的焊接引脚、PID 数值或可直接烧录的固件。板级资源和电机负载只有拿到实物/原理图才能确认。
OLED 的 I2C 地址、近距传感器阈值、BMS 状态与电量估计同样在此阶段接入。

## ROS 接口合同

| 数据 | 话题 | 要求 |
| --- | --- | --- |
| 2D 雷达 | `/mooncar/scan` | LaserScan，米/弧度，扫描平面 TF（仿真为 `lidar_scan_frame`），建议 >=10Hz |
| 深度 | `/mooncar/depth/image` | Image，32FC1 米或 16UC1 毫米，光学坐标系 |
| 相机内参 | `/mooncar/depth/camera_info` | 与深度同分辨率、已校准、同 frame |
| IMU | `/mooncar/imu` | Imu，SI 单位、ENU/轴向核对、有效协方差；不要直接融合失真的磁航向 |
| 轮编码器 | `/joint_states` | 四关节 FL/FR/RL/RR，弧度；底层顺序和方向一致 |
| 原始里程计 | `/odom` | 由已有 wheel_odometry 产生；硬件需校准协方差 |
| 运动指令 | `/cmd_vel` -> `/mooncar/cmd_vel_safe` | Twist，m/s、rad/s，经限速/超时保护后进入桥 |
| 链路状态 | `/mooncar/hardware/status` | DiagnosticArray；解锁服务见 UART 协议 |

真机统一 `use_sim_time=false`。TF 必须使用实测安装尺寸；EKF 启动后只能由 EKF 发布
`odom -> base_footprint`，此时关闭 wheel_odometry 的 `publish_tf`。
当前 `hardware.launch.py` 仅用于电机台架，默认只由轮里程计发布该 TF。

仿真保留 `/mooncar/scan_raw`，标准 `laser_filters` 包围盒过滤器剔除车体范围内回波，
输出 `/mooncar/scan`。真机应按实测外形配置该过滤器；不要扩大包围盒来隐藏外部障碍。
软件回归脚本关闭自动 ROS 发现，虚拟编码器与控制测试不应连接正在运行的真机 ROS 图。

## 真机验收门槛

每项记录日期、硬件版本、软件提交、参数、日志/视频和结论。没有记录即未验收。

- 电气：电流/温度/欠压/短路防护与独立急停符合所选器件约束；连续运行不掉电重启。
- 控制：四轮方向正确，闭环跟踪与起步死区可控；通信中断和程序失效均能独立停止。
- 定位：直线距离、原地转角、闭环返回误差按实际测量标定；不能用仿真误差宣称实车精度。
- 感知：强光、暗色石块、无纹理沙地、近距盲区和真实坑沿逐项测试；缺测不得视为安全地面。
- 导航：受控场地完成多目标、临时障碍、人工取消、断连与急停；记录碰撞、路径和终点误差。
- 工况：分别评估地球重力下的坡道/沙地打滑、续航与热负载；月球重力仿真不代表地球实车动力学。

地形算法只分析可见几何，不测土壤承载力。松软沙地当前通过人工禁行区表达，自动材料分类与
滑移/沉陷模型需实测数据后再训练或标定。二维平面 Nav2 也不等价于完整三维越野规划器。
