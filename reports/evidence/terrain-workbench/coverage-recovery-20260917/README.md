# 有效覆盖率不足的定向修复与单轮验证

结论：在 `visible_curve_v1`、第二起点 `(6.5,-2,2.4)`、8 m 活动半径和覆盖优先 v2 策略下，修复后的单轮任务以 300 仿真秒为预算上限，在 282.1 秒因无新安全候选点结束。固定评价区域 198.875 m² 上，**C=81.65%，达到暂定 80% 门槛**；原始观测覆盖率 88.43%。这只验证该场景该起点的一轮，不代表三策略、多场景或实物验收的覆盖保证。

整体 `mapping-acceptance-v1.1` 仍未通过：P=81.99%，低于暂定 90%；S=66.94。有效估计的高程 RMSE 为 1.38 cm，坡度 MAE 为 2.50°。468 个有估计但不合格的格子中，456 个坡度误差超过 5°（其中 33 个同时高程误差超过 5 cm）。未改变评价分母、参考地表、5 cm/5° 容差或 80%/90% 门槛。

## 原因与修复

90 秒正式对照的 54 轮全部 C<80%；修复运行层后的同条件 90 秒覆盖优先轮 C=36.83%。第一次延长到 300 秒的诊断在 212.5 秒因一个目标长期恢复而故障结束：Nav2 多次报告前方碰撞和路径不可达，车辆在凸起地形附近几乎不前进，轮子里程计与实际位姿分离。该轮原始观测覆盖率 60.97%，但 C 只有 25.86%；真值位姿仅用于离线诊断的同观测重放时 C=52.80%，说明单纯修正定位或继续等待都不足以直接达到 80%。

共同执行层现在对导航反馈设置停止条件：至少 3 次恢复，且连续 15 仿真秒未将目标剩余距离改善 0.15 m 时，取消当前候选动作并重新规划；已失败的位置不换朝向重复尝试。传感器失效、越界、任务超时等原有安全停止仍终止任务。第一次修复验证在约 105 秒成功取消受阻目标，却暴露代价地图更新后新候选点被发令前安全检查拒绝会误停整个任务；现将这种目标不可通行拒绝记录为候选失败，避开该点后重新选点。第一次修复验证原始失败记录保留。

最终轮 17 个动作全部成功，路程 22.29 m，0 个失败动作；未现场触发新的取消或候选拒绝分支，因此这些分支的现场证据来自第一次修复验证，最终轮证实带修复代码的任务可完成当前场景的 C 门槛，不能将两轮的路径差异全部归因为单一代码改动。

因此这个条件下可采用 **300 仿真秒上限**；任务自身在 282.1 秒停止，约 281 秒采集时首次观察到 C 超过 80%。时间序列是对同一原始档案做前缀重放，并非多次独立实验。其他场景的适宜预算需要先定条件再验证，不能把本轮结果推广成通用时间。
